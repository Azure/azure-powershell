Running Azure Batch Scenario Tests:

The scenario tests (ScenarioTests folder) replay the HTTP requests saved in the SessionRecords folder ("Playback", the
default). Record a test again only when its requests change. Recording runs against a real Batch account and costs money
when pools have nodes.

To record (full steps: documentation/testing-docs/using-azure-test-framework.md):

1. Sign in to Azure PowerShell with your user account (Connect-AzAccount). The test framework uses that sign-in.

2. Point the test framework at the test subscription and switch it to Record mode:
  Import-Module ./tools/Modules/TestFx-Tasks.psd1
  Set-TestFxEnvironment -UserId <your e-mail> -SubscriptionId <subscription id> -TenantId <tenant id> -RecorderMode "Record"
  $env:AZURE_TEST_MODE = "Record"
This writes C:\Users\<you>\.Azure\testcredentials.json. Instead, you can set
  $env:TEST_CSM_ORGID_AUTHENTICATION = "Environment=Prod;SubscriptionId=<subscription id>;TenantId=<tenant id>;UserId=<your e-mail>;"
An existing testcredentials.json overrides $env:TEST_CSM_ORGID_AUTHENTICATION and $env:AZURE_TEST_MODE. Check for an
old one, and remove it if you use the environment variables.

3. Set the Batch account the tests use. Record in a Batch account that is only for these tests: some tests delete pools
by name, also pools they didn't create (for example TestPoolCRUD removes pool1 and pool2 at the end, even if it couldn't
create them). Batch service requests sign in with the account's shared key.
Set-TestFxEnvironment doesn't change the Azure PowerShell context that Get-AzBatchAccountKey uses, so first select the
same subscription:
  Set-AzContext -Subscription <subscription id>
  $env:AZURE_BATCH_ACCOUNT = "<account name>"
  $env:AZURE_BATCH_ACCESS_KEY = (Get-AzBatchAccountKey -AccountName "<account name>" -ResourceGroupName "<resource group>").PrimaryAccountKey
  $env:AZURE_BATCH_ENDPOINT = "https://<account name>.<region>.batch.azure.com"
  $env:AZURE_BATCH_RESOURCE_GROUP = "<resource group>"

4. Build, then run only the tests you want to record, for example:
  dotnet test src/Batch/Batch.Test/Batch.Test.csproj -c Debug --no-build --filter "FullyQualifiedName~ScenarioTests.PoolTests.TestPoolCRUD"
The new recordings replace the files in SessionRecords.

5. Before you commit them, check the new recordings for secrets (keys, SAS tokens, passwords). The recorder replaces
most of them with "Sanitized".

6. Switch back to playback: $env:AZURE_TEST_MODE = "Playback", and Set-TestFxEnvironment ... -RecorderMode "Playback"
(or delete testcredentials.json).

Pools and cost:
- The tests create the pools they need. Pools with 0 nodes cost nothing; nodes do.
  Tests that need running nodes (for example ComputeNodeTests and ComputeNodeUserTests) need dedicated core quota in
  the account.
- When recording, pools created by a test's C# setup (ScenarioTestHelpers) are deleted after the test, also when the
  test fails. This clean-up skips a pool that was already there, but the tests' own deletes don't (see step 3). It
  doesn't cover pools created inside a .ps1 script: after recording, check for pools left behind (Get-AzBatchPool) and
  remove them.

==================================================================================================================================
This project is divided into Unit Tests and Scenario Tests.
All the Scenario Tests can be found under the ScenarioTests folder.  All other test classes are Unit Tests.

The Unit Tests run in the xUnit test framework.
xUnit Documentation: https://xunit.net/

The Unit Tests make use of the Moq framework to create mock objects of the PowerShell runtime and the
management libraries.
Moq Documentation: https://github.com/Moq/moq4/blob/master/README.md

Unit Tests for cmdlets that use the Batch OM make use of BatchClientBehaviors.
Using this feature, we insert custom behaviors into the OM service requests that allow
us to modify the Batch request objects, the actions performed on them, and their responses.
BatchClientBehaviors Documentation: https://msdn.microsoft.com/en-us/library/azure/microsoft.azure.batch.batchclientbehavior.aspx

The Scenario Tests use the record and playback test framework in tools/TestFx. See
documentation/testing-docs/using-azure-test-framework.md for more information.
